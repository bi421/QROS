# Institutional Footprint Engine — Validation Plan

**Version:** `0.1.0` — draft; synthetic tests only until Phase 5 gates.

## 1. Validation questions

1. Does each adapter preserve source events, units, ordering, timestamps, and provenance?
2. Are derived quantities and Delta/CVD arithmetically correct and deterministic?
3. Do detectors identify the preregistered synthetic patterns and reject adversarial near-misses?
4. Can any feature or event use data that was not yet available at its `available_at_utc`?
5. Do feed gaps, stale quotes, sequence loss, contract changes, or unknown aggressor side cause fail-closed behavior?
6. Can every report event be traced to exact raw inputs, definitions, and code revision?

## 2. Synthetic truth fixtures

Create hand-computable fixtures with explicit expected outputs for:

- Single unusually large print vs normal print distribution.
- Large prints clustered vs same volume dispersed outside the window.
- Positive delta with positive price progress.
- Positive delta with negligible/negative price progress.
- Negative delta with negative price progress.
- Negative delta with negligible/positive price progress.
- High unknown-side volume reducing classified coverage.
- Stale quote, locked quote, crossed quote, quote/trade timestamp tie, and out-of-order quote.
- Exchange aggressor flag conflicting with quote inference (keep streams distinct; never silently overwrite).
- L2 depth depletion followed by replenishment.
- L2 sequence gap invalidating book until a fresh snapshot.
- Sweep through a pre-existing level followed by acceptance vs rejection.
- Trade correction/cancel and duplicate delivery.
- Contract roll boundary and session reset boundary.

Expected values must be calculated independently by hand/reference functions, not generated by the detector under test.

## 3. Property and invariant tests

- Delta equals classified buy quantity minus classified sell quantity exactly in native units.
- CVD equals cumulative delta under the registered reset policy.
- Adding unknown-side quantity does not change signed delta but reduces or preserves coverage.
- Permuting events with valid sequence numbers must not alter canonical replay output; invalid sequence must be rejected/flagged, not silently sorted.
- Replaying the same raw bytes/config twice yields identical output hashes.
- Appending future events cannot alter already-emitted historical outputs.
- Removing required quote/L2 inputs cannot create a positive detector event.
- No L2-derived output after an unresolved sequence gap before snapshot recovery.
- Contract-specific tick-size and quantity units are enforced.
- Every event's `available_at_utc` is at or after the latest required input event/quote availability.

## 4. Adversarial tests

- A large print on an auction/cross condition must not automatically count as continuous aggressive flow.
- A large print without known side must not contribute to signed delta.
- Large positive delta with price rising strongly is not absorption.
- High delta with a single quiet price bar but no persistence is not absorption.
- Apparent replenishment caused by snapshot reset or sequence gap is not valid replenishment.
- Price wick without trade-through evidence is not a sweep.
- A single large print cannot establish participant identity.
- Missing/partial venue coverage cannot be reported as total-market volume.

## 5. Temporal and leakage audit

For every feature and detector, record its latest contributing event timestamp and receive/availability timestamp. Run prefix-invariance tests: compute output at cutoff T, append all events after T, recompute, and assert outputs available by T remain byte-identical. Verify quote-based aggressor classification only uses eligible prior quotes under source clock semantics. Verify swing levels from Market Structure are used only after their confirmation timestamp.

## 6. Metrics (only after independent labels exist)

- Precision, recall, false-positive rate, false-negative rate.
- Event-level time-to-detection and detection latency.
- Coverage and abstention rate (`INSUFFICIENT_DATA`).
- Results stratified by contract, session, volatility, and source quality.
- Inter-rater/label agreement and label provenance.
- Stability across adjacent threshold choices, reported as a sensitivity surface rather than selecting the best threshold.

Labels must be independently defined and blind to detector output. If reliable labels cannot be created, report reproducibility and synthetic correctness only; do not claim real-world detection accuracy.

## 7. Phase gates

- Phase 0 documentation: no code or market data changed.
- Phase 1 contracts: immutable typed contracts + synthetic fixtures; unit tests and Ruff pass.
- Phase 2 features: reference arithmetic, replay, property tests; synthetic only.
- Phase 3 detectors: all truth and adversarial fixtures pass; no positive events on invalid inputs.
- Phase 4 temporal audit: prefix invariance, deterministic replay, lineage checks pass.
- Phase 5 real data: require verified license, exact feed/product semantics, schema sample, sequence/correction behavior, contract metadata, storage/hash plan, and a source-quality acceptance report. If any gate fails, remain `BLOCKED_DATA_SOURCE`.
- Phase 6 detector validation: preregister labels, windows, thresholds, metrics, and independent sample before evaluation.
- Phase 7 strategy study: separate preregistration; no strategy work is included in engine acceptance.

## 8. Required report language

Allowed: “unusually large print observed in this feed,” “aggressive buy activity inferred by quote test,” “absorption candidate,” “displayed-depth replenishment candidate,” “pattern consistent with sustained large participation.”

Not allowed without independent evidence: “Bank X bought,” “institutional accumulation confirmed,” “smart money entered,” “iceberg detected,” “market makers trapped,” or “this event predicts price rise.”
